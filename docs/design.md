# 03 Design v0.1 — 야간 보행자 동행 로봇

상태: 팀 검토 전  |  대응 요구사항: R-01~R-06 (`docs/requirements.md`)

## D06 시스템 구조와 정보 흐름

```text
스마트폰 호출 ─┐
구간 호출 버튼 ├→ 요청 접수·배차 → 로봇 주행·동행 → 위치·상태 기록 → 운영 상황실
              │
비상 버튼 ────┴→ 긴급 사건 처리 ─┬→ 112 신고 경로
                                └→ 운영 상황실 경보
```

로봇은 직접 조종되는 장치가 아니라 지정 경로와 안전 조건에 따라 스스로 이동한다. 배차기는 순찰 중인지, 다른 보행자를 동행 중인지에 따라 요청을 대기열에 놓거나 이용 가능한 로봇에 배정한다. **실제 112 연동과 배차 서버는 첫 MuJoCo 장면의 범위 밖**이며, 장면에서는 사건과 결과를 기록하는 모의 입력으로 표현한다.

### 모듈 사이 정보(ICD 초안)

| 사건 | 입력 | 출력/받는 곳 |
| --- | --- | --- |
| 동행 호출 | 호출 방식(스마트폰/버튼), 경로 ID, 호출 지점, 시각 | 접수 ID, 배차 상태, 로봇 ID 또는 대기 상태 |
| 동행 시작·종료 | 로봇 ID, 보행자 지점, 경로 안의 종료 지점 | 로봇의 목표 지점, 종료 기록 |
| 비상 입력 | 버튼 ID, 위치, 시각, 사건 ID | 같은 사건 ID를 가진 112용 알림과 상황실용 경보 |
| 로봇 상태 | 위치, 순찰/접근/동행/정지 상태, 장애 상태 | 배차기와 상황실 상태 표시 |

각 사건의 단위는 위치 `m`, 시각 `s`(시뮬레이션)로 통일한다. 실제 신고에 필요한 개인정보·영상 전송 항목은 기관 협의 전에 확정하지 않는다.

## D07 MuJoCo 장면 구성표

| 요소 | 첫 장면의 표현 | 목적 |
| --- | --- | --- |
| 보행 구간 | 편도 500 m 또는 2,000 m, 폭 3 m의 직선 보행로 | 거리별 순찰·호출 시간 비교 |
| 로봇 | 폭 약 0.7 m의 바퀴형 이동체 1대 | 이동 경로·보행 폭 확인 |
| 보행자 | 경로 안의 위치를 바꿀 수 있는 인체 표지 | 동행 종료 지점 표시 |
| 호출 지점 | 출발점·중간·끝점의 호출 버튼 표지 | 위치별 호출 장면 |
| 비상 지점 | 호출 지점과 구별되는 비상 버튼 표지 | 긴급 사건 장면 |
| 정류장·주거지 | 출발점과 경로 안의 주거지 표지 | 이동 상황 시각화 |
| 차량 공간 | 보행로와 분리된 도로 표지 | 로봇의 보행 구역 이탈 확인 |

장면은 실제 도시 지도를 재현하지 않는다. 지역에 따라 경로를 바꿀 수 있도록 길이 `L`을 생성 스크립트의 매개변수로 둔다. 첫 버전은 직선 구간이며, 골목·교차로·경사·다중 로봇은 이후 장면에서 추가한다.

첫 장면의 로봇과 보행자는 위치를 바꿀 수 있는 **mocap 표지**다. 실제 바퀴 구동·경로 추종·충돌 감지를 구현한 동적 모델이 아니므로, 장면이 열린다는 사실만으로 안전 요구사항의 통과를 주장하지 않는다.

## D08 안전 개념

| 위험 | 첫 설계 대응 | 확인 방법 |
| --- | --- | --- |
| 보행자와 충돌 | 보행자와의 간격 유지, 장애물 발견 시 정지 | 충돌 0회 기록 |
| 보행 통로 막힘 | 폭 3 m 장면에서 로봇이 한쪽으로 이동·정지 | 남는 통행 폭 1 m 이상 계산 |
| 차도로 이탈 | 로봇 목표 지점을 지정 보행 경로 안으로 제한 | 경로 밖 진입 0회 |
| 호출 중복·로봇 사용 중 | 요청별 사건 ID와 대기 상태 표시 | 중복 배차 0회 |
| 비상 신호 누락 | 하나의 비상 사건을 112용·상황실용 알림으로 각각 기록 | 두 알림 기록 5/5회 |
| 장난 누름·오작동 | 비상 버튼 덮개 또는 길게 누르기 검토, 기록 보존 | 실제 장치 단계에서 검증. 긴급 신고 지연 여부 함께 평가 |

몸으로 범죄자를 막는 기능은 이 장면의 안전성을 확인할 수 없어 첫 설계의 주행 동작에 포함하지 않는다. 향후 별도 위험 평가가 필요하다.
