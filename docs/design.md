# 03 Design v0.2 — 야간 보행자 동행 로봇

상태: 팀 검토용  |  대응 요구사항: R-01~R-03, S-01~S-03 (`docs/requirements.md`)

## 이번 개발에서 구현하는 정보 흐름

```text
보행 연결 지도 + 차단 구간 정보 → 경로 탐색 → 임시 로봇 표지 이동
                                              ↓
                                MuJoCo 좌표를 가상 위치값으로 읽기
                                              ↓
                                목적지 오차·경계 이탈 기록
```

차단 구간 정보는 시나리오가 미리 제공합니다. GPS 수신이나 장애물 센서 판별은 구현하지 않습니다. 현재 MuJoCo 표지는 물리적으로 구동되는 바퀴 로봇이 아니라 경로·위치 처리 흐름을 보여주는 대상입니다. 자세한 완료 기준은 [개발 범위](development-scope.md)에 정리했습니다.

## D06 후속 서비스 구조 구상(이번 개발 범위 밖)

```text
스마트폰 호출 ─┐
구간 호출 버튼 ├→ 요청 접수·배차 → 로봇 주행·동행 → 위치·상태 기록 → 운영 상황실
              │
비상 버튼 ────┴→ 긴급 사건 처리 ─┬→ 112 신고 경로
                                └→ 운영 상황실 경보
```

아래 흐름은 전체 서비스의 장기 구상입니다. 이번 단계에서 배차, 호출, 비상 입력, 실제 112 연동은 실행하거나 합격 판정하지 않습니다.

### 모듈 사이 정보(ICD 초안)

| 사건 | 입력 | 출력/받는 곳 |
| --- | --- | --- |
| 동행 호출 | 호출 방식(스마트폰/버튼), 경로 ID, 호출 지점, 시각 | 접수 ID, 배차 상태, 로봇 ID 또는 대기 상태 |
| 동행 시작·종료 | 로봇 ID, 보행자 지점, 경로 안의 종료 지점 | 로봇의 목표 지점, 종료 기록 |
| 비상 입력 | 버튼 ID, 위치, 시각, 사건 ID | 같은 사건 ID를 가진 112용 알림과 상황실용 경보 |
| 로봇 상태 | 위치, 순찰/접근/동행/정지 상태, 장애 상태 | 배차기와 상황실 상태 표시 |

각 사건의 단위는 위치 `m`, 시각 `s`(시뮬레이션)로 통일합니다. 실제 신고에 필요한 개인정보·영상 전송 항목은 기관 협의 전에 확정하지 않습니다.

## D07 MuJoCo 장면 구성표

| 요소 | 첫 장면의 표현 | 목적 |
| --- | --- | --- |
| 보행 구간 | 편도 500 m 또는 2,000 m, 폭 3 m의 직선 주거 골목 보행로 | 경로 탐색·가상 위치 확인 |
| 로봇 | **형태 미확정.** XML에는 장면 배치용으로 폭 약 0.7 m의 임시 4바퀴형 표지 1대를 넣음 | 이동 경로·보행 폭을 설계할 때 필요한 공간 확인 |
| 보행자 | 경로 안의 위치를 바꿀 수 있는 인체 표지 | 동행 종료 지점 표시 |
| 호출 지점 | 출발점·중간·끝점의 호출 버튼 표지 | 위치별 호출 장면 |
| 비상 지점 | 호출 지점과 구별되는 비상 버튼 표지 | 긴급 사건 장면 |
| 출발 거점·주거지 | 골목 밖 출발 거점과 경로 양쪽의 주거지 표지 | 이동 상황 시각화 |
| 차량 공간 | 첫 장면에는 큰 도로를 넣지 않았습니다. 보행 경로의 경계만 표시했습니다. | 차도·차량 간섭은 후속 장면에서 별도 검증합니다. |

장면은 실제 도시 지도를 재현하지 않습니다. 지역에 따라 경로를 바꿀 수 있도록 길이 `L`을 생성 스크립트의 매개변수로 둡니다. 첫 버전은 직선 구간 안의 두 개 보행 연결선을 탐색용 그래프로 사용합니다. 골목·교차로·경사·다중 로봇은 이후 장면에서 추가합니다.

첫 장면의 로봇과 보행자는 위치를 바꿀 수 있는 **mocap 표지**입니다. 바퀴형·사족형·이족형 가운데 최종 형태는 아직 정하지 않았습니다. 현재 XML의 바퀴는 **임시 외형**이며, 실제 바퀴 구동·경로 추종·충돌 감지를 구현한 동적 모델이 아닙니다. 따라서 장면이 열린다는 사실만으로 안전 요구사항의 통과를 주장하지 않습니다. 형태 후보와 구상 이미지는 [로봇 형태 비교](robot-form-options.md)에 정리했습니다.

## D08 안전 개념

| 위험 | 첫 설계 대응 | 확인 방법 |
| --- | --- | --- |
| 보행자와 충돌 | 보행자와의 간격 유지, 장애물 발견 시 정지 | 후속 동적 모델·센서 단계에서 검증 |
| 보행 통로 막힘 | 폭 3 m 장면에서 로봇이 한쪽으로 이동·정지 | 남는 통행 폭 1 m 이상 계산 |
| 보행 경로 이탈 | 로봇 목표 지점을 지정 보행 경로 안으로 제한 | 경로 밖 진입 0회. 차량 교통 영향은 별도 평가 |
| 호출 중복·로봇 사용 중 | 요청별 사건 ID와 대기 상태 표시 | 후속 서비스 단계에서 검증 |
| 비상 신호 누락 | 하나의 비상 사건을 112용·상황실용 알림으로 각각 기록 | 후속 서비스 단계에서 검증 |
| 장난 누름·오작동 | 비상 버튼 덮개 또는 길게 누르기 검토, 기록 보존 | 실제 장치 단계에서 검증. 긴급 신고 지연 여부 함께 평가 |

몸으로 범죄자를 막는 기능은 이 장면의 안전성을 확인할 수 없어 첫 설계의 주행 동작에 포함하지 않습니다. 향후 별도 위험 평가가 필요합니다.

### 비상 대응 외형 구상(미구현)

바퀴형과 4족형에 대해 [비상상황 이미지](../assets/concepts/emergency/README.md)를 만들었습니다. 제안한 반응은 **비상 입력 → 112용·상황실용 알림 생성 → 표시등과 큰 음성·경고음 → 보행자 곁에서 통행 공간 유지** 순서입니다. 위협자에게 접촉하거나 보행자를 몸으로 막는 성능은 주장하지 않습니다. 실제 소리 크기, 조명 방식, 기관 연동과 위협 상황에서의 효과는 이후 결정·검증합니다.
