# D03 요구사항 명세 — 1차 개발 범위

상태: 팀 검토용 v0.3 · 관련 문서: [문제 정의](problem.md), [개발 범위와 완료 기준](development-scope.md), [설계](design.md)

## ① 요구사항 계층

| 층 | 이번 단계에서 원하는 결과 |
| --- | --- |
| Stakeholder | 야간 보행자 동행 로봇의 핵심 이동 기능을 먼저 검증합니다. 지정 보행 구간의 목적지에 도달할 수 있는지, 막힌 구간을 피해 갈 수 있는지 확인합니다. |
| System | 500 m와 2,000 m 대표 장면에서 통행 가능한 보행 연결만 사용해 경로를 고르고, 시뮬레이션 위치값을 확인하며, 목표 지점 1 m 이내에 도착합니다. |
| Subsystem | 경로 탐색기는 막힌 연결을 제외합니다. 위치 모듈은 MuJoCo의 로봇 좌표를 **가상 위치 입력**으로 읽습니다. 이동 시연은 선택된 지점을 따라 임시 로봇 표지를 옮기고 결과를 기록합니다. |

수치와 장면은 팀이 정한 **시뮬레이션 조건**입니다. 실제 GPS 정확도, 장애물 인식, 자율 주행 성능 또는 범죄 예방 효과의 측정값이 아닙니다.

## ② 이번 단계의 Must 요구사항

| ID | 종류 | 한 가지 요구사항 | 합격 기준 | 확인 |
| --- | --- | --- | --- | --- |
| R-01 | 기능 | 지정된 보행 연결에서 시작점부터 목적지까지 경로를 탐색합니다. | 500 m와 2,000 m에서 정상 경로를 각각 찾습니다. 경로가 없으면 실패를 명시합니다. | T-01, T-03 |
| R-02 | 기능 | 통행 불가로 표시된 연결을 경로에서 제외합니다. | 직접 연결을 막은 두 장면에서 해당 연결을 사용하지 않고 열린 우회로를 찾습니다. | T-02 |
| R-03 | 기능 | MuJoCo의 가상 위치값을 읽어 선택된 경로를 따라 목표 지점까지 이동 시연합니다. | 정상·차단 조건 × 500 m·2,000 m의 4회에서 목표 오차 1 m 이하입니다. | T-04 |

**Must는 3개입니다.** 한 단계가 실패하면 그 단계에서 멈추고, 다음 기능을 추가하기 전에 원인을 수정합니다.

## ③ 별도 안전·검증 조건

| ID | 조건 | 이번 단계에서 확인 가능한 범위 | 확인 |
| --- | --- | --- | --- |
| S-01 | 지정 보행로 밖으로 이동하지 않습니다. | 각 위치 기록에서 임시 로봇 중심이 보행로 경계 안에 있는지 확인합니다. 로봇 외형 반폭 0.38 m를 고려합니다. | T-04 |
| S-02 | 막힌 연결을 통과하지 않습니다. | 경로 계획 결과에 차단 연결이 포함되지 않는지 확인합니다. 장애물 자동 감지는 포함되지 않습니다. | T-02 |
| S-03 | 사람·차량과 충돌하지 않습니다. | **이번 단계의 합격 판정에서 제외합니다.** 임시 mocap 표지는 물리적으로 구동되는 로봇이 아니며, 현재 장면의 통과 기록만으로 충돌 안전을 입증할 수 없습니다. | 후속 개발 |

1 m는 첫 시뮬레이션의 목표 도착 판정용 **팀 가정**입니다. 로봇 위치는 MuJoCo의 정확한 내부 좌표를 읽으므로, 그 오차가 0 m여도 실제 GPS 성능을 뜻하지 않습니다.

## ④ 우선순위와 개발 제외 항목

| 우선순위 | 기능 | 처리 |
| --- | --- | --- |
| Should | 동행 호출 후 보행자에게 접근하는 절차 | 핵심 이동 기능을 통과한 뒤 설계합니다. |
| Could | 여러 로봇의 배차 및 대기 시간 비교 | 별도 단계에서 검토합니다. |
| Won't(이번 단계) | 스마트폰 앱, 구간 호출·비상 버튼, 외부 유지 장치 연동 | 장면의 외형 표지는 남아 있으나 기능 연결은 구현하지 않습니다. |
| Won't(이번 단계) | 실제 GPS 수신기, 카메라·라이다를 통한 통행 판별, 실제 지도 | 가상 좌표와 시나리오가 제공하는 통행 가능 정보만 사용합니다. |
| Won't(이번 단계) | 실제 112·상황실 전송, 경고음, 범죄자 방어 | 장기 구상으로만 유지합니다. 실제 신고 및 신체 안전을 주장하지 않습니다. |

`src/judge.py`와 `tests/test_judge.py`는 **이전 요구사항 초안의 입력 기록 판정 예제**입니다. 현재 Must의 실행 결과는 `src/navigation.py`, `tools/run_navigation_demo.py`, `tests/test_navigation.py`로 확인합니다. 기존 판정 예제의 통과를 이번 단계의 합격으로 합산하지 않습니다.

## ⑤ 시험과 완료 판정

| 시험 | 입력 | 기대 결과 |
| --- | --- | --- |
| T-01 | 열린 500 m·2,000 m 경로 | 시작→중간→끝 경로 반환 |
| T-02 | 중간→끝 직접 연결 차단 | 열린 우회 연결만 사용 |
| T-03 | 출발 연결까지 차단 | 갈 수 없다는 오류 반환 |
| T-04 | MuJoCo 장면 2개 × 정상·차단 조건 | 가상 위치값 기록, 목적지 오차 ≤1 m, 보행로 밖 위치 기록 0건 |

네 조건을 모두 자동 시험하고, 시연 명령의 결과에 `passed: true`가 나와야 **이번 단계의 핵심 기능 완료**로 판정합니다. 이 판정은 전체 로봇의 완성을 뜻하지 않습니다.
