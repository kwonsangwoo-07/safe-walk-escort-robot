# D01 문제 정의서 — 야간 보행자 동행 로봇

D01 · 작성: 프로젝트 팀(대화 기반 초안) · 검토: 팀 전원 예정 · 상태: 작성 · v0.1 · 관련 [D03 요구사항](requirements.md), [03 Design 초안](design.md)

## 해결하려는 문제

지하철역·버스정류장·큰길에서 주거지로 이어지는 어둡고 인적이 드문 **지정 보행 구간**에서, 혼자 걷는 사람이 주변을 계속 경계하고 도움을 요청할 수단을 직접 찾아야 하는 부담을 줄이고자 합니다. 로봇은 이 구간을 순찰하다가 호출한 보행자와 함께 이동하고, 비상 입력을 운영 상황실과 112 신고 경로에 전달하도록 설계합니다. **범죄율 감소나 실제 안전 확보는 아직 입증하지 않았습니다.**

## 대표 사용자와 이용 범위

- **대표 사용자(문제 설명용):** 야근 후 밤 11시 무렵 집 근처 지하철역에 도착한 20~30대 직장인. 집으로 가려면 조명이 약하고 인적이 드문 주거 보행 구간을 지나야 합니다.
- **실제 이용 대상:** 직업·성별·연령을 제한하지 않는 야간 보행자. 대표 사용자는 설명을 구체화하기 위한 사례일 뿐 서비스 제한이 아닙니다.
- **운영 시간:** 지역의 일몰 무렵부터 일출 전까지. 저녁 7~8시는 계절에 따른 예시이며 고정 시작 시각은 아닙니다.
- **운영 구간:** 지역별 범죄·환경 자료와 현장 확인을 거쳐 선정할 보행 구간. 지하철역·버스정류장·큰길을 출발 거점으로 두고 지정 구간을 왕복합니다. 집이 경로 안에 있으면 집 앞, 밖에 있으면 지정 구간의 종료 지점까지 동행합니다.

## 로봇이 없을 때의 현재 흐름(As-Is)

`① 역·정류장에 도착 → ② 귀가 경로를 선택 → ③ 어두운 주거 구간에 진입 → ④ 구간을 혼자 걸으며 주변과 뒤쪽을 반복해서 확인 → ⑤ 불안하면 밝은 길로 우회하거나 지인에게 연락 → ⑥ 위험하다고 느끼면 휴대전화로 신고·도움 요청 → ⑦ 집 또는 구간 끝에 도착`

③~⑥은 귀가할 때마다 나타날 수 있는 구간입니다. 이어폰 소리를 줄이거나 주변을 살피는 행동은 **가능한 대처의 예시**이며 모든 보행자가 똑같이 행동한다는 조사 결과는 없습니다. 위험 상황 자체가 매번 발생한다는 뜻도 아닙니다.

## 로봇이 맡는 한 단계와 사람에게 남는 일

로봇이 맡는 핵심 단계는 **④ ‘어두운 지정 구간을 혼자 걸으며 주변을 경계하는 단계’**입니다. 이를 위해 로봇이 반복 순찰하고, 스마트폰 또는 고정 호출 버튼의 요청을 받아, 보행자와 경로 안의 종료 지점까지 이동합니다. ⑥에서 도움이 필요할 때 비상 버튼 입력으로 112용 알림과 운영 상황실 경보를 동시에 만드는 보조 기능도 목표로 합니다.

보행자는 목적지와 동행 요청 여부를 결정하고 직접 걷습니다. 위험한 상황의 판단과 현장 출동은 사람·관계 기관의 몫입니다. 로봇이 범죄자를 물리적으로 제압하거나 안전을 보장하는 기능은 현재 검증 범위에 넣지 않습니다.

## 현재 불편을 숫자로 표현하기

| 지표 | 현재 값·단위 | 근거와 한계 |
| --- | --- | --- |
| 혼자 지나야 하는 대표 구간 길이 | 편도 **500 m**, 장거리 조건 **2,000 m** | 사용자가 제안한 시뮬레이션 대표 조건입니다. 특정 지역을 측정한 값은 아닙니다. |
| 해당 구간을 혼자 걷는 시간 | 각각 **8분 20초**, **33분 20초** | 보행 속도를 **1 m/s**로 둔 `거리 ÷ 속도` 계산입니다. 현장 보행 시간은 미측정입니다. |
| 불안감·우회 거리·도움 요청 횟수 | **미측정** | 현장 관찰이나 보행자 인터뷰가 아직 없어 수치를 만들지 않았습니다. |

위 길이와 시간은 실제 범죄 위험이나 로봇의 예방 효과를 나타내지 않습니다. 향후 후보 구간을 정한 뒤 실제 거리·조도·보행 폭·통행량을 확인하고, 이용자의 불안감과 우회 행동을 별도 조사해야 합니다.

## 시뮬레이션에서 따로 잴 것

| 지표 | 측정 방법 |
| --- | --- |
| 순찰 경로 완주 | 편도 500 m·2,000 m에서 출발점→중간→끝점→중간→출발점의 5개 방문 기록 |
| 호출 후 도착 시간 | 로봇이 비어 있을 때와 다른 보행자를 동행 중일 때를 구분해 초(s)로 기록 |
| 동행 완료 | 보행자의 경로 안 종료 지점과 로봇의 정지 위치 차이를 m로 기록 |
| 통행·주행 안전 | 보행자·장애물 충돌 횟수와 경로 밖 진입 횟수를 기록 |
| 비상 신호 | 한 입력에 대해 112용·상황실용 알림이 각각 만들어졌는지 기록 |

현재 [MuJoCo 장면](../scenes/safe_walk_500m.xml)은 배치만 표현한 v0입니다. 위 성능의 실제 측정 결과는 아직 없습니다. [판정 코드](../src/judge.py)의 단위 테스트가 통과한 것과 로봇이 순찰에 성공한 것은 별개입니다.

## 왜 이동 로봇이 필요한가

| 검사 질문 | 이 프로젝트의 답 |
| --- | --- |
| 물리적으로 이동하거나 닿아야 합니까? | 로봇이 지정 구간을 이동하며 보행자와 위치를 맞춰 동행해야 합니다. |
| 같은 동작을 반복합니까? | 호출이 없을 때 경로를 왕복 순찰하고, 요청이 오면 접근·동행·복귀를 반복합니다. 실제 하룻밤 호출 횟수는 미측정입니다. |
| 사람이 불편하거나 위험합니까? | 대표 상황에서 어둡고 인적이 드문 구간을 혼자 이동하며 주변을 계속 살펴야 합니다. 불안감의 크기와 사고·범죄 위험은 현장 조사 전입니다. |
| 앱·고정 장치만으로 해결됩니까? | 스마트폰과 고정 버튼은 호출·신고를 도울 수 있습니다. 요청자의 위치로 이동해 **함께 걷는 기능**은 이동 로봇이 맡습니다. 동행이 실제 불안감이나 범죄에 주는 효과는 별도 검증이 필요합니다. |

## 검토에서 확인할 질문

- 후보 구간에 계단·높은 턱·급경사가 있습니까? 이에 따라 바퀴형·4족형·이족형 중 이동 형태를 결정합니다.
- 편도 2 km에서 로봇 한 대의 호출 대기 시간이 길어질 때 로봇 추가 배치나 구간 분할이 필요합니까?
- 보행로 폭이 좁을 때 로봇이 멈추거나 양보할 기준은 무엇입니까?
- 실제 112 신고 연동에는 어떤 기관 협의와 운영 절차가 필요합니까?

팀원·이용자의 검토 의견은 아직 수집하지 않았습니다. 위 질문을 검토받아 문서를 수정합니다.
